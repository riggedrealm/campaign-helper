# Retcon: load-bearing slips and repairs

Open this playbook when Voyage's latest output broke canon or the player-agency rules, or contradicts something already established.

Decide in this order: first whether the slip is load-bearing, then which turn it is in, and treat everything else as a small slip.

## 1. Is the slip load-bearing?

A slip is load-bearing when it would carry forward and change the story: a main NPC killed or misidentified, a player action decided for the player, a secret blurted, a death, a wrong place or time that would carry forward, a changed job premise or terms, a quest's giver or goal changed, or what an NPC asked for changed. <!-- RET-1 -->

If the slip is none of these, it is a small slip: go to step 3.

## 2. A load-bearing slip: which turn is it in?

If the slip is in Voyage's latest turn, file a Studio story fix now, before the next prompt. Filing and timing are in `director/playbooks/studio.md`, STU-6, and writing the fix is STU-9; the next prompt then assumes the fixed version. Never let a changed premise pass as harmless. <!-- RET-2 -->

If the slip is in an older turn, Studio cannot edit it, because Studio edits only the latest turn. Fix it in the fiction, in the next prompt: a rumour, a misunderstanding, something staged. <!-- RET-3 -->

## 3. A small slip

A small slip stays a prompt fix or a `Facts:` fix. Write the fix the way `core.md`, Prompt format, writes `Facts:` (FACTS-1), and re-send only what is essential, as actions (`core.md`, The turn, LOOP-4). <!-- RET-4 -->

## Asking the user

Ask the user out of game when the next prompt cannot repair the problem, and always before Voyage's regenerate or undo. <!-- RET-5 -->

## Recording the repair

Record what the players saw. The log follows the output the players read, not the version you would have preferred. After a Studio story fix that is the corrected turn, and the turn's payload summarises it. After a fix in the fiction it is the slip as it appeared and then the repair as it plays. Log the slip itself under `slips` (`core.md`, Bookkeeping, LOG-2). <!-- RET-6 -->
